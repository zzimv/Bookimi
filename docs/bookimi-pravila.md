# БУКИМИ — правила работы в папке проекта (проект)

Эти правила действуют во всех чатах папки «Букими». Если правило противоречит прямой просьбе владелицы в чате — спросить её.

## Общение
1. Пишем по-русски, просто, «как для чайников». Ответы короткие, по пунктам.
2. **Пока идёт обсуждение — ничего не делаем.** Если владелица пишет «поясни», «опиши», «ничего не делай» — только отвечаем.
3. **Новое решение — сначала спросить.** Ничего не добавлять и не менять по своей инициативе (пример: «скоро» на книгах). Непонятно — задать короткий вопрос с вариантами.
4. Перед каждым шагом **с деньгами или персональными данными** — короткое описание и ждать подтверждения.
5. Экономить токены: делать минимально нужное, без лишних проверок и повторов; большие задачи — одним агентом, а не несколькими.

## Данные и безопасность
6. Все персональные данные — только на серверах в РФ. Зарубежные сервисы ПДн не получают.
7. Согласия — отдельными галочками, по умолчанию сняты. Фото удаляются через 7 дней.
8. Зарубежный ИИ — только за флагом и после отдельного согласия.
9. Секреты — только в `.env` (права 600), ничего секретного в `NEXT_PUBLIC_*`.
10. Реальные фото детей — только с письменным согласием родителей. Фото сына владелицы и её образцы не копировать в репозиторий и демо.
11. Тест узнаваемости: если не прошла ни одна модель — остановиться и показать результаты.

## Контент
12. Тексты книг фиксированные: подставляются только имена, герои, род и повод. Новые книги — только по решению владелицы.
13. Имена — всегда с заглавной буквы и в правильном падеже.
14. Нигде нет слов «нейросеть», имён художников, студий, мультфильмов и брендов (в текстах, стилях, промптах, интерфейсе).
15. Не публикуем выдуманные отзывы и истории как настоящие (истории-примеры — с пометкой).
16. Чужие сервисы (например, Wonderbly) — только как идея; их рисунки, тексты и макеты не копируем.

## Демо и сайт
17. Работаем в ветке `demo-work`; `main` — «сайт», его файлы не трогаем без команды.
18. **Каждая версия демо — отдельная страница**: rev 01, rev 02… Старые версии не перезаписывать.
19. Перед выдачей версии: проверка типов, тесты, `npm run check:responsive` (12 экранов) и просмотр скриншотов глазами.
20. В каждом ответе о версии: что изменилось, что не идеально, какие решения ждут владелицу.

## Документы
21. Итоговые документы для владелицы и команды — в папке проекта (`claude/…`): статус и ТЗ, логика, артефакты, блог, правила.
22. После крупных решений — обновить `claude/bookimi-status.md` (статус и ТЗ проекта).
