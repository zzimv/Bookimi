## Контент-движок (4 аудитории)

    (аудитория, сегменты, голос, стили, вид героя, поводы, тема, план) обновляются при каждом seed, тексты витрины, SEO,
    обложка и включение из админки — не перезаписываются. Пустая/недоступная БД — каталог берётся из реестра.
36. Поводы: посадочные страницы для всех 24 поводов профилей (кроме «свой» и «без повода»); любой сюжет дарится на любой
    повод — повод вплетается в развороты 1 и 12 (`applyOccasion`), на странице повода сначала сюжеты с этим поводом.
37. Вход: телефон обязателен (+7, мобильный), код приходит на почту (настройка `auth.phoneRequired`, по умолчанию да).
    Сотрудникам и покупателям с уже сохранённым телефоном телефон при входе не нужен. Телефон, закреплённый за другим
    аккаунтом, не переносится — покупателя просим войти с почтой того аккаунта.
38. Смена настроения иллюстраций: до оплаты — бесплатно перерисовываются обложка и 2 разворота превью, не больше
    2 раз (`limits.moodChangesPreview`) и только в пределах суточного лимита расходов; после оплаты первая смена
    перерисовывает всю книгу (13 иллюстраций) и PDF бесплатно, каждая следующая списывает одну бесплатную перерисовку,
    а когда они кончились — платно, как перерисовка (`limits.redrawPriceRub`, через поддержку). Пока картинок нет —
    настроение просто запоминается.
39. «Своя история»: голос — выбор покупателя, иначе первый голос сегмента (`segment.textStyleIds[0]`); сегмент — явный,
    иначе по возрасту героя (питомцы — по виду: собака/кошка). Демо-текст своей идеи — сюжет сегмента в этом голосе.
40. Стиль картинок другой аудитории (например, детская акварель для кошки): из промпта убирается фраза художника о
    «своём» герое и добавляется описание героя по виду; спорящие слова негатива (например, «human body» у стилей
    питомцев для ребёнка) убираются. Если сцена прямо просит костюм — запрет костюмов снимается (просьба art/pets.ts).
41. Подписи PDF по аудитории: «Сказка, в которой…» — только для детей, для остальных — «История, в которой…»;
    возрастная маркировка на обложке: дети и питомцы 0+, подростки 6+, взрослые 12+ (сверить с юристом по 436-ФЗ).
42. Демо-рендер: доп. герои стоят рядом с героем без перекрытия (шаг по ширине фигур, группа сдвигается в кадр),
    вторая половинка — в полный рост героя, хозяева питомца — чуть дальше и мельче, чтобы питомец оставался главным.


## Витрина и анкета (UX, как у Wonderbly)

43. Сначала книга, потом герой. Книга выбрана (карточка, страница книги, повода — `?skazka=`) — анкета не спрашивает ни повод,
    ни сюжет: Герой → Внешность и что любит → Кто ещё в сказке → Стиль и посвящение (шаг «Кто ещё» пропускается, если добавить
    некого: у пар имя второй половинки — на шаге «Герой»). Повод такой книги — из ссылки (`?povod=`), иначе единственный повод
    книги (новогодняя, ко дню рождения), иначе «без повода». Без книги: «Для кого книга?» → «Какой повод?» с книгами под чипсами
    (сначала написанные к поводу — «к вашему поводу», остальные — «впишем ваш повод»; для «Своего повода» первой — «Своя история»).
44. Согласия — один раз, в первой точке сбора данных: путь с фото — две отдельные галочки перед загрузкой (ПДн; фото — по
    аудитории: «как законный представитель» / «своё фото или с согласия изображённых» / фото питомца), на входе — «Согласие
    дано ✓»; без фото — галочка ПДн на входе. Сервер не требует согласие повторно, если оно уже есть (по аккаунту или анонимной
    cookie) и не создаёт дублей; согласия до входа закрепляются за аккаунтом. Тип в БД для фото — `CHILD_PHOTO` для всех аудиторий.
    Рассылка — отдельная необязательная галочка только на входе.
45. Сезон на главной: с 15 октября по декабрь — Новый год (кнопка «Выбрать новогоднюю книгу», пункт меню); режим и срок печати
    меняются в Настройках → «Сезон на главной». Срок печати по умолчанию: праздник − 7 дней доставки − 5 рабочих дней печати.
46. Подписка «−300 ₽» на главной видна только при активном промокоде в Настройках → «Подписка на главной»; подписка создаёт
    покупателя с согласием на рассылку и показывает промокод (письмо не отправляется).
47. Иллюстрации на витрине, в каталоге и «живая обложка» анкеты — демо-рендер `/obrazec` (SVG, подписано «пример»). Настоящие
    пары «фото → иллюстрация» — только с письменного согласия, через `public/showcase/showcase.json` (см. README там же).
48. Тёмная тема: системная по умолчанию, переключатель в подвале (Авто/Светлая/Тёмная, хранится в браузере).

## Исправления по ревью (контент и безопасность)

49. Название с «[Имя]» — один помощник `src/content/title.ts`: падеж по предлогу перед [Имя] (о/об/при → предложный,
    для/у/от/без → родительный, к/по → дательный, с/за/под → творительный, иначе именительный); им пользуются текст
    книги, бриф, живая обложка анкеты, карточки каталога, страница книги, SEO и PDF (через текст книги).
50. Предлог перед подставленным именем/поводом исправляет fillTags: «об» перед а, о, у, э, и, ы (перед е, ё, ю, я —
    «о»: «о Юле»), «со» перед стечением согласных (Льв-, Вс-, Св-, Ст-, Зв-, Шк-…), «ко» — перед Вс-/Мн-; регистр сохраняется.
51. Свободный текст анкеты (внешность, приметы, характер питомца, как познакомились, воспоминания, описания и «что это»
    доп. героев, свой повод, идея) перед YandexGPT обезличивается (`src/lib/gen/redact.ts`): все падежные формы имени,
    домашнего имени, доп. героев и частые ласковые формы из таблицы (Аня ↔ Анна/Анечка/Анюта…) + уменьшительные
    суффиксы → метки {ГЕРОЙ.*}/{ЛАСКОВО.*}/{ДОПn.*}; в промпт картинок — «the hero», «the friend». Телефоны, почта,
    ссылки, @ники и числа от 6 цифр удаляются. Имена-слова (Любовь, Лев, Вера…) ищем только с заглавной. Редкие
    домашние имена, которых нет в таблице и которые не образованы суффиксом от имени, распознать нельзя — поэтому
    под полями подсказка «Имена здесь не нужны — мы подставим их сами».
52. Промокод и скидка новичка не суммируются: побеждает та, что даёт больше рублей на этом заказе (при равенстве —
    скидка новичка, промокод не тратится). Применённый промокод записывается в заказ; при оплате usedCount растёт
    одним условным UPDATE (`usedCount < maxUses`). Если лимит исчерпан между заказом и оплатой — оплата принимается,
    владельцу уходит уведомление.
53. Списание лимитов книги (переписать, перерисовка, смена настроения до/после оплаты) — условный UPDATE
    (`updateMany` с проверкой остатка и статуса); в очередь задача ставится, только если списание прошло.
54. Повод в тексте — короткая форма (`OCCASION_WORDS`: «годовщина», «выход на пенсию», «новоселье», «первое сентября»…)
    с родом и падежами ({ПОВОД.дат}); «свой повод» не склоняется. В начале фразы, строки или цитаты — с заглавной.
55. «Месяц ясный» (дети): ребёнок не выходит из дома один — Сова прилетает к окну, путешествие — сон под её крылом.
56. Стихи: имя и повод — только отдельной строкой-обращением вне метра, не больше 4 имён на книгу; в стихотворных
    строках — «ты», «весь дом», «непоседа», формы рода равной длины (дедушка/бабушка). Правило — в системных промптах
    стихотворных голосов и в validateContent.
57. Вход: код — только на почту; цель-телефон ({target:"+7…"}) принимается лишь при включённой настройке
    «Вход по SMS-коду» (`auth.smsLogin`, по умолчанию выключено). Телефон обязателен и при проверке кода (если
    `auth.phoneRequired` и у покупателя его нет) — проверяется до кода и сохраняется в профиль.
58. Сказки в сутки: кроме лимита устройства — лимит по подсети IP (IPv4 /24, IPv6 /64), по умолчанию 10
    (`limits.textsPerIp`). Текст YandexGPT, как и превью, ждёт в очереди, если исчерпан суточный лимит расходов (демо — бесплатно).
59. Заголовок `Origin: null` или некорректный Origin у POST к /api — 403 (раньше — 500).

## Ближайшие праздники

60. Вкладка «Ближайшие праздники» (/prazdniki) заменила в шапке сезонный пункт («Новый год»): он менялся по сезону,
    а вкладка видна всегда. Список — настройка `holidays` в таблице Setting (JSON, без новой модели Prisma), правится в
    админке → «Праздники» (владелец и маркетолог; оператор — только просмотр, право `holidaysEdit`). Пока записи нет —
    значения по умолчанию из кода: Новый год (31.12), Рождество (07.01), Старый Новый год (14.01), «Дни рождения» (всегда).
61. Правила дат: каждый год (день-месяц), N-й день недели месяца (День матери — последнее воскресенье ноября), разовая дата
    (праздник «плавает» — дату меняют каждый год), «всегда». Все даты — по Москве (UTC+3). Праздник виден за «показывать
    за N дней» (по умолчанию для зимних — 90, чтобы в конце октября были видны все три).
62. «Заказать до»: дата − доставка (верхняя граница СДЭК до ПВЗ из Настроек → Доставка, 7 дней; если СДЭК выключен — самый
    быстрый включённый способ) − печать (PrintHouse.leadDaysMax, 5 рабочих дней). Нерабочие дни: сб, вс, праздники ТК РФ
    (1–8 января, 23 февраля, 8 марта, 1 и 9 мая, 12 июня, 4 ноября) и 31 декабря; переносы по постановлениям не учитываем
    (срок — с запасом). Можно задать вручную «за N дней». Для «всегда» — «за 14 дней». После срока — «PDF в тот же день».
63. Новые поводы `rozhdestvo` и `staryj-novyj-god` (все аудитории): общие крючки — зимний семейный праздник (огоньки,
    снег, ёлка), без религиозных утверждений; сюжеты со своим `default` используют его с {ПОВОД}. Сезонная кнопка на главной
    в режиме «auto» берёт ближайший видимый праздник с датой (ручной режим и ручной срок печати — как раньше), полоса промо —
    тоже, пока печать успевает (выключается: Настройки → Полоса промо → «Ближайший праздник вместо текста»).
64. Кабинет: «Ближайшие дни рождения ваших героев» — герои с датой рождения (сохранённые и из анкет книг), 60 дней на главной
    кабинета, год — в «Мои герои»; кнопка ведёт в анкету с поводом «день рождения» и героем.
65. Триггер `hero_birthday` «День рождения героя через 21 день» добавлен в DEFAULT_RULES **включённым**: сообщение
    маркетинговое, уходит только при согласии на рассылку (отписка его снимает), не чаще 1 в сутки, с контрольной группой
    и автоостановкой. Окно — 21…19 дней (если в 21-й день сработал лимит «1 в сутки»); одно напоминание на героя (по имени)
    в год — общее для старого правила `birthday` и нового. В существующей базе seed добавит правило выключенным, если
    старое `birthday` включено.

    изменение с сохранением копирайта — он указан в поле `source` файла. В набор входят города новых регионов, как в
    списке СДЭК. Кодов СДЭК в открытых данных нет: известны только Москва (44) и Санкт-Петербург (137), остальные `null`.
Д2. **Подсказки** `GET /api/geo/cities?q=` (с 2 букв, 120 запросов/мин с IP, кэш ответа 1 ч): нормализация ё→е, регистр,
    дефисы/тире, «г.»/«город», английская раскладка («rjhjktd» → Королёв); ранг: точное → начало названия → начала слов
    по порядку («нижн нов», хвост может уточнять регион: «королев моск») → второе слово («петербург») → опечатка
    (≥ 4 букв, та же первая буква, 1 ошибка, с 7 букв — 2); внутри ранга — по населению. С ключами СДЭК к офлайн-списку
    добавляются коды и малые населённые пункты из `GET /v2/location/suggest/cities` (LRU в памяти: 1000 запросов, сутки).
    Город не из списка принимается — тогда тариф «ориентир», а списка пунктов нет.
Д3. **Пункты выдачи** `GET /api/geo/pvz?city=&region=&code=&q=` — `GET /v2/deliverypoints?city_code=…&is_handout=true`
    (код города — из подсказки или `GET /v2/location/cities`, кэш 7 дней; список пунктов — 6 ч, 300 городов), поиск по
    улице/дому/метро на сервере, до 30 пунктов в ответе. Без ключей СДЭК списка нет — поле «код или адрес пункта» вручную.
    «Показать на карте» — ссылка Яндекс Карт только с координатами пункта. При оформлении сервер сверяет код пункта со
    списком СДЭК и берёт адрес оттуда; СДЭК недоступен — заказ принимается, пункт сверяет оператор.
Д4. **Цена и срок** пересчитываются при смене города/пункта: калькулятор СДЭК по коду города (`to_location.code`), без
    кода — по индексу или адресу. Без ключей — тариф из настроек ± пояс по расстоянию от склада (`SHIP_FROM_CITY`,
    по умолчанию Москва): до 80 км −40 ₽/−1 день, до 800 км — база, до 2000 км +90 ₽/+1, до 4000 км +190 ₽/+3, дальше
    +340 ₽/+6. Выключается: Настройки → Доставка → «с поправкой на удалённость».
Д5. **Миграция 0004_delivery_points**: `Shipment.cityCode/pvzCode/pvzAddress` (пункт уходит в `delivery_point`
    `POST /v2/orders` через `cdekOrderInput`), `User.savedAddresses` JSONB — адресная книга (последние 3). SQL написан
    вручную и сверен с `prisma migrate diff --from-empty`. Курьер: улица и дом, квартира/офис, комментарий; Почта —
    индекс обязателен (6 цифр).
Д6. **Подстановка** (`pickPrefill`): вошедший — 1) последний адрес из адресной книги; 2) если книга ни разу не заводилась
    (NULL) — последний заказ с доставкой, кроме оформленных без «Сохранить адрес» (`noPrefill`); 3) имя и телефон профиля.
    Если покупатель удалил все адреса в «Мои данные» (книга = []), прошлые заказы не подставляются. Новый покупатель —
    телефон из черновика анкеты. Недоступный сейчас способ не подставляется (переносится только город).
    Отдельной «гостевой» подстановки нет: оформление требует входа, а данные получателя в браузере не храним.
Д7. «Сохранить адрес для следующих заказов» включено по умолчанию; адреса — только на сервере в профиле, правка и
    удаление — «Мои данные» → «Адреса доставки» (город и пункт меняются при оформлении), выгрузка `/api/me` включает
    `savedAddresses` и адреса отправлений, удаление аккаунта очищает книгу и адреса отправлений.
Д8. Демо: те же подсказки по офлайн-списку (в демо — 400 крупнейших городов, сжатым), пункты — детерминированные
    «демо-пункты» на город (3–24 шт., метро для 7 городов), подстановка — из прошлого демо-заказа.

## Мультфильм по книге
М1. **Цена не названа владелицей.** Доп «Мультфильм по книге» (DIGITAL) — **690 ₽** по умолчанию (`cartoon.priceRub`), «Своим
    голосом» (MODIFIER, только вместе с мультфильмом или к уже купленному) — **400 ₽** (`cartoon.ownVoiceRub`, как сказала
    владелица). Цену мультфильма нужно утвердить: Настройки → «Мультфильм по книге». Мультфильм покупается при оформлении книги
    и позже из кабинета («Добавить мультфильм» → заказ только с цифровыми допами, `addonsOnly`, та же оплата). Промокод и скидка
    новичка действуют и на мультфильм. В списке допов при оформлении мультфильм идёт после аудио и раскраски (`sortOrder` 9–10).
М2. **Что получает покупатель:** MP4 H.264 1080×1080, 25 fps, AAC 160 кбит/с, ~2:00 (90–150 с, `cartoon.targetSec`), −16 LUFS;
    плюс вертикальная версия 9:16 **720×1280** (`cartoon.verticalHeight`; 1080×1920 можно включить, но это +~100 с CPU на рендер,
    дорого для 2 vCPU) и постер JPEG. Сцены: заставка-обложка с названием → 12 разворотов → «Конец» + посвящение +
    «Сделано с любовью в БУКИМИ». Кодирование: `-preset veryfast -tune animation -crf 23` (размер вдвое меньше CRF 20 при
    SSIM 0,9915 против 0,9924 — разницы глазом нет).
М3. **Движение без видеомодели:** камера (наезд/панорама/отъезд по композиции; рамка героев всегда целиком в кадре, ноги — по
    возможности выше субтитров), у демо-иллюстраций — параллакс: фон и герои рисуются отдельными слоями (`renderDemoSpread`
    `layer: background | mask`), герои дышат/«шагают»/покачиваются; у картинок с GPU — камера + лёгкое «дыхание» (точка интереса —
    `sharp` attention). Переходы — наплыв и «через белое», частицы по теме (снег, светлячки, искорки, пылинки) + виньетка.
    Задел `CARTOON_I2V=wan` / `cartoon.i2v` — интерфейс `ImageToVideo` (src/lib/gen/cartoon.ts), выключен: на GPU-сервере нет `/v1/i2v`.
М4. **Демо-иллюстрации разворотов стали разными:** раньше у темы был один фон на всю книгу (12 одинаковых снежных полей).
    Теперь по описанию сцены разворота (`scene`) рисуется реквизит (`src/content/art/props.ts`: река, мост, окно/домик с огнями,
    комната со стеной и полом, кровать, сани, подарки, наряженная ёлка, домики, салют, лес, зайчонок, дверь, шкаф, когтеточка,
    клубок, чай, лампа, плёнка, пылесос, коробка) и тон неба (ночь/утро/вечер). Это меняет и демо-картинки самой книги — книга
    и мультфильм совпадают. Цвет одежды героев теперь один на всю книгу: из палитры стиля по имени героя (`outfitFor` в pipeline),
    раньше менялся от разворота к развороту. Уже сохранённые демо-книги перерисуются при следующей генерации/смене настроения.
М5. **Звук без чужих записей:** фоновая музыка синтезируется (пэд аккордами + «музыкальная шкатулка», лад по настроению),
    шелест страницы — синтез из шума; музыка приглушается под голос (`sidechaincompress`), итог — loudnorm в два прохода.
    Свой лицензированный трек — файл в хранилище `books` (например `music/lullaby.mp3`) и ключ в `cartoon.music`.
М6. **Сценарий:** 14 реплик (название, 12 разворотов, «Конец» + посвящение), ~220–260 слов на 2 минуты (2,25 слова/с, ~10 с на
    разворот). Демо — по правилам (первые предложения разворота в пределах бюджета, добор/срезка до общего бюджета,
    `cartoonScript` — чистая функция, без Node API — для демо-стенда). YandexGPT — текст с метками `{ГЕРОЙ.*}` (имена
    обезличены redact.ts, посвящение в модель не уходит), имена подставляем у себя; ответ проверяется (`validScript`), иначе — правила.
    Длительность сцены — по фактической длительности озвучки (ffprobe); короче 90 с — паузы растягиваются.
М7. **Голос диктора:** SpeechKit, голос по аудитории (`cartoon.voiceByAudience`: дети — Алёна, подростки — Филипп, питомцы —
    Джейн), покупатель может сменить. В демо — «речь без слов» (формантный синтез по слогам текста) с тем же темпом, что и
    оценка сценария, — чтобы тайминг демо совпадал с настоящим; это заглушка, а не TTS.
М8. **Свой голос:** страница «Озвучить своим голосом» в кабинете: «С чего начать», требования к формату, отдельное
    **невыставленное** согласие (тип `VOICE`, новая запись enum в миграции 0005), запись по репликам в браузере (индикатор
    уровня, «слишком громко/тихо», волна) или одна загрузка (режем по паузам). Формат — по сигнатуре файла; ≥ 22,05 кГц, моно/
    стерео, ≤ 50 МБ, ≤ 3 мин. Обработка: срез низа, мягкий afftdn, обрезка тишины и длинных пауз, общий для всех реплик
    loudnorm (−16 LUFS, два прохода). Клонирования голоса нет, записи третьим лицам не передаются (обработка — ffmpeg у нас).
    Записи удаляются через 30 дней после выдачи мультфильма своим голосом (задача воркера каждый день в 03:40), сразу — при
    отзыве согласия или по кнопке; сам мультфильм остаётся у покупателя. Сценарий после начала записи не меняется (реплики
    записаны) — правка текста книги на мультфильм своим голосом не влияет.
М9. **Пересборка:** одна бесплатная (`cartoon.freeRerenders`) при смене голоса, субтитров или текста книги («ничего не изменилось» —
    отказ); если рендер упал — повтор бесплатный. Своим голосом — до 3 сборок (`cartoon.ownVoiceBuilds`). Дальше — через поддержку.
М10. **Ссылка «Поделиться»:** случайный токен на 30 дней (`/mult/<токен>`), отзывается в кабинете; noindex в metadata,
    `X-Robots-Tag` (middleware и выдача файлов) и Disallow `/mult/` в robots.txt; на странице нет имени покупателя и данных заказа.
М11. **Ресурсы:** рендер — в воркере (ffmpeg 5.1+ в образе), по одному мультфильму; сцены — короткими роликами по ядру,
    затем сборка. Память воркера поднята до 1 ГБ (`docker-compose.yml`); на VPS 2 ГБ это впритык — при нехватке выключите
    вертикальную версию или поднимите тариф. Шрифт субтитров — Nunito (OFL), TTF в `src/lib/gen/fonts`.

## Путь создания: герои с фото в начале, группа, «книга для каждого»
П1. **Порядок шагов** (`src/lib/flow.ts`): книга выбрана заранее — Герои → (Группа) → Детали; «Создать книгу» — Герои →
    Для кого и повод → Книга → (Группа) → Детали; аудитория и повод из ссылки (`?dlya=&povod=`) — шаг «Для кого и повод»
    пропускается. Дальше — текст → подтверждение → вход → превью → оформление. Полоса прогресса считает только шаги
    анкеты; число шагов меняется, когда выбрана книга о группе (+«Группа»). Это заменяет порядок из п. 24 и 43–44: согласия
    и фото теперь в начале, а не после текста (решение владельца).
П2. **На первом шаге** «Кто герой?» (ребёнок/подросток/взрослый/питомец) — это и есть аудитория; на шаге 2 её можно
    поменять (поля героя сбрасываются, имя и фото человека сохраняются). Доп. герои добавляются здесь же (роль, имя, фото или
    пара слов), роль под сюжет уточняется на «Деталях»; обязательные роли сюжета (вторая половинка, хозяин) — тоже там.
П3. **Согласия** — один раз, перед первой загрузкой: две отдельные неотмеченные галочки (ПДн + фото, формулировка по
    аудитории), `/api/draft/consent`, по анонимной cookie и/или аккаунту, без дублей. Фото других детей группы — третья
    отдельная галочка «родители этих детей разрешили» (тип `GROUP_PHOTO`, миграция `0006_group_flow`), по умолчанию
    советуем описание словами. На входе — «Согласие дано ✓»; путь без фото — галочка ПДн на входе, как раньше.
П4. **Фото обрабатывается сразу на сервере** (`src/lib/photo-process.ts` + общий `photo-check.ts`): тип по первым байтам,
    EXIF-поворот, JPEG без метаданных до 2048 px (исходник — для выбора другого лица), портрет «голова и плечи» 1024×1024
    (кадр 2,3 лица, центр ниже лица — как `preprocess.py`), медиана 3 + уровни 1–99% + лёгкая резкость. Проверки: < 500 px и
    сильный смаз (резкость < 15) — отказ; лицо < 160 px «слишком мелко», < 256 px «небольшое», яркость вне 60…200, низкий
    контраст, несколько лиц (второе > 35% площади главного) — подсказка и выбор лица на исходнике. Лицо ищется эвристикой
    (кожа в YCbCr + тёмные «глаза» в верхней половине) — нейросетевых детекторов в репозитории нет, а WASM-детекторы
    (face-api/tfjs, mediapipe) весят мегабайты и тянут лицензии моделей. Эвристика ошибается на очень тёмной коже, бежевом
    фоне и светлых волосах — поэтому «лицо не нашли» — подсказка, а не отказ (GPU-проверка лица перед рисованием остаётся).
    Резкость нормируется на контраст лица (тёмное, но резкое фото не «смазано»). Цвет волос / окрас — только предложение
    «Отметить». В ИИ фото не уходит до шага превью.
П5. **Срок фото**: без книги — `limits.photoTtlNoBookHours` = 24 ч (анонимный черновик `QuizDraft`), после создания книги
    фото переезжают к героям книги со сроком 7 дней от загрузки. Задача `purgePhotos` удаляет и портрет, и исходник, а фото
    черновика старше текущего значения настройки — даже если при загрузке срок был длиннее. Черновик в браузере хранит
    только id фото; после перезагрузки ссылки обновляются, удалённые id убираются.
П6. **Шаг «Книга»** — разделы повода `sectionsOf` (`src/content/sections.ts`), та же функция в `plotSections` на сервере,
    в анкете и на `/povod/[slug]` и `/skazki?povod=` (раньше — плоский список «к поводу / остальные»). Анкета фильтрует
    по возрасту героя (если книг такого возраста нет — без фильтра). Скрытые сильной темой — «Показать все книги (N)».
П7. **Группа**: вставка списком (строки, запятые, «;», номера, маркеры, пометка «(м)/(ж)»), пол по имени, неоднозначные
    (Саша, Женя, Валя, Шура, Слава, Сеня, Стася, Вася, Сима, иностранные на -и/-о) — спрашиваем; повторы и совпадение с
    именем героя — просим букву фамилии («Маша К.»). Фото детей группы в нейросеть не передаются (30 референсов модель не
    примет): из фото берём только подсказку описания; фото ребёнка становится фото героя его копии в заказе «для каждого».
П8. **«Книга для каждого в группе»** (`src/lib/bulk.ts`, `bulk-server.ts`): копии — отдельные книги с `Book.parentBookId`,
    в каждой герой — свой ребёнок, в группе — все остальные (включая героя основной книги), взрослые, повод, сюжет, стиль —
    общие; личные доп. герои (мама, игрушка) не копируются. Посвящение — один шаблон с метками ({ГЕРОЙ.дат}, {Р:…|…}).
    Тексты первых `bulk.previewCopies` = 3 книг (с основной) — сразу и без подтверждения по одному, их превью — вслед за
    основной (без лимита «1 превью на контакт»: это один заказ); остальные сочиняются и рисуются после оплаты.
    **Скидки по количеству — ждут решения владельца**: по умолчанию 5+ −20%, 15+ −30%, 25+ −35% (`bulk.tiers`; меняются в
    админке → Настройки → «Книга для каждого в группе», с проверкой, см. Т9). Со скидкой новичка и промокодом не суммируются — берётся большая. Допы в таком
    заказе не продаются. Одна доставка на всех (в сад/школу или одному родителю), до ПВЗ СДЭК — бесплатно от 2 книг (как
    раньше). В заказе — строка на каждую книгу (bookId), чек НПД — одна услуга на сумму заказа (как `issueReceipt`).
П9. **Демо-стенд**: обработка фото — в браузере тем же `photo-check.ts` (canvas, портрет 512 px, только в памяти вкладки);
    чтобы HTML остался ~750 КБ, длинные строки рисовальщиков и текстов витрины собираются в сжатые таблицы
    (`packStrings` в `tools/demo/build.mjs`, проверено: 280 разворотов рендерятся байт в байт), городов — 400 вместо 600.

## Исправления по отчёту тестирования 30.10.2026 (сервер)
Т1. **2FA.** `totpSetupAction` выдаёт ключ только пока 2FA не включена; включена — только ввод кода (новый ключ из сессии

    одноразовых кодов восстановления `xxxx-xxxx` (в БД — sha256 с id сотрудника; показываются один раз, пока не нажато
    «Я сохранил(а)»; можно перевыпустить со свежим кодом), вход по коду восстановления — алерт владельцу. Сессия сотрудника
    — 12 часов (cookie и проверка `createdAt`, в т. ч. для старых сессий). **Свежий код (10 минут)** нужен для: возврата,
    подтверждения перевода, реквизитов/налогового режима/способов оплаты/SMTP/цен (audio, cartoon, bulk, referral, alerts),
    цен форматов и допов, типографий, ролей. Без него — `/admin/2fa?reauth=1&next=…`, после кода действие нужно повторить
    (форма не пересылается автоматически — так проще и безопаснее). В демо без включённой 2FA проверки нет (как и раньше).
    Сброс 2FA сотруднику, потерявшему телефон и коды, — пока только через БД (`totpEnabled=false`) владельцем.
Т2. **Оплата не зависит от почты.** `markPaid`: в одной транзакции — платёж, статус заказа, промокод, `paidFull` и задачи
    `generate-full` (pg-boss пишет задачу через соединение транзакции — outbox без отдельной таблицы). После коммита —
    чек, письма, реферал, триггеры, лимит НПД, каждый шаг отдельно (`step`): сбой → журнал и алерт владельцу. Письма
    покупателю — `notifySafe`: не ушло ни в один канал → задача `send-notification` (до 6 повторов с нарастающей паузой от
    минуты), очередь недоступна → `notify.failed` в журнал. Так же — в оформлении заказа, подтверждении перевода, статусах,
    возврате, генерации, триггерах, «Приведи друга». Код входа: сбой отправки → 503 «Не получилось отправить письмо…»,
    код аннулируется. Алерты владельцу (`alertOwner`) по-прежнему best-effort.
Т3. **Двойная оплата.** Платёж и заказ блокируются `SELECT … FOR UPDATE`, статус меняется условно. Успешный платёж по уже
    оплаченному заказу → `Payment.status = needs_refund`, алерт «Повторная оплата — вернуть деньги», `payment.duplicate` в
    журнал, без чека, промокода и писем; в карточке заказа — красная плашка. Возврат по такому платежу — вручную (СБП/
    перевод) — автоматического возврата второго платежа нет. «Оплатить» тем же способом, пока заказ ждёт оплаты и срок не
    вышел, возвращает тот же платёж (тот же ключ идемпотентности провайдера); другой способ — новый платёж. «Подтвердить
    оплату» по уже оплаченному заказу (двойной клик) ничего не делает.
Т4. **Сотрудники и покупательские API.** `ownBook` больше не открывает чужие книги сотрудникам (ни просмотр, ни фото,
    ни PDF, ни правка, ни превью — превью к тому же не меняет владельца книги). Для поддержки — `/api/admin/books/[id]` и
    `/download` (право `books`: владелец, оператор; каждое открытие — в журнал), исходные фото детей — право `photos`
    (только владелец; в карточке заказа оператор их тоже не видит). Маркетолог — без книг, фото и PDF. Страница заказа
    `/zakaz/[id]` и `/api/orders/[id]` — только покупателю; демо-чек — покупателю и праву `orders`.
Т5. **Печать после PDF.** Оплата заказа по уже готовой книге (FULL_READY) ставит ту же задачу, но `runFull` идёт в режим
    «только недостающее»: блок и обложка печати формата заказа, аудио/раскраска, если их нет, мультфильм, передача в
    типографию — без перерисовки и без пересборки PDF (книга не уходит в FULL_QUEUED). «Передать в печать» (кнопка и
    `sendToPrint`) — только когда заказ оплачен, все книги заказа FULL_READY и есть блок и обложка; перепечатка — из
    любого статуса после оплаты.
Т6. **Удаление аккаунта** (`src/lib/account.ts`). Удаляются: книги целиком (тексты, страницы, иллюстрации, превью, PDF,
    аудио, записи голоса, мультфильмы, листы персонажа — из БД и хранилища, по папке книги), герои и фото (портрет и
    исходник), черновики анкеты, коды входа, журнал отправленных сообщений на адреса покупателя, каналы уведомлений,
    сессии. Обезличиваются: обращения в поддержку (контакт «удалён», имена и контакты в тексте → «[имя]», «[контакт]»),
    опубликованные отзывы (автор «Покупатель», имена в тексте → «[имя]»; неопубликованные — удаляются). Остаются **для
    налогового учёта (НПД, 5 лет)**: заказы с суммами, датами, статусами, составом (название книги в строке → «персональная
    книга»), платежи и чеки; контакты, адрес и UTM заказа — удаляются. Согласия (Consent) остаются как доказательство их
    получения (без контактов). Пока печатный заказ в работе (оплачен, не доставлен) — удаление откладывается с понятной
    причиной (иначе типографии нечего печатать). Задачи pg-boss с адресом в данных удаляются самим pg-boss по сроку хранения.
Т7. **CI.** Тесты на БД сами задают реквизиты продавца и способы оплаты (`tests/helpers/db-setup.ts`), мультфильм — своя
    книга на тест; проверено `vitest run --sequence.shuffle` (файлы и тесты в случайном порядке) и на чистой базе.
Т8. **Зачёт PDF** — сколько фактически заплачено за PDF (цена минус его доля скидки заказа), за вычетом зачёта, уже
    использованного в оплаченных заказах печати этой книги (дважды не зачитывается); не больше цены формата (как раньше).
Т9. **Проверка настроек** (`src/lib/settings-validate.ts`, zod): диапазоны чисел (пустое поле — ошибка, а не 0), ИНН с
    контрольной суммой (`innIsValid`; пустой — можно, пока продажи не начаты), ФИО ≥ 2 слов, телефон/карта/почта, порты,
    проценты 1–100, длительность мультфильма min ≤ цель ≤ max, даты. Ошибка — текст у раздела, ничего не сохраняется.
    Скидки «для каждого» — строка «5:20, 15:30, 25:35»: пороги по возрастанию, скидка 1–90% и не убывает, до 6 порогов.
    Промокод: код 3–30 (латиница, цифры, дефис), ровно одна скидка — 1–90% или фикс. от 1 ₽ до цены самого дорогого
    активного формата, лимит ≥ 1, «действует с/до» (до — в будущем, не раньше «с»), дубль — «уже есть». Цены форматов
    ≥ 1 ₽, допов ≥ 0 ₽ / 1–90%; статус заказа вручную — только шаги после оплаты.
Т10. **Триггерные письма.** `{name}` склоняется по предлогу перед ним («про Машу», «у Маши», «об Ане»), `{name.дат}` — явный
    падеж, `{book}`/`{Book}` — «сказка» для детских книг и «книга» для остальных, `{hero_role}` — «главный герой /
    главная героиня». Уже сохранённые в БД тексты правил «Сказка про {name}» и «— главный герой» правятся при подстановке.
Т11. **Возврат** — только из оплаченных статусов и один раз (условный UPDATE); ЮKassa: ответ проверяется (не 2xx или
    canceled — возврат не проведён, заказ не меняется, ошибка в карточке), ключ идемпотентности — от платежа. После
    полного возврата книга теряет `paidFull` (PDF и файлы закрываются), если не оплачена другим заказом. В журнал —
    причина, сумма, провайдер, ответ провайдера, ошибка аннулирования чека.
Т12. **Воркер, пачка сказок**: каждая задача пачки — отдельно; лимит расходов откладывает только свою сказку на 15 минут,
    ошибка — книга FAILED и до двух повторов отдельной задачей (раньше pg-boss повторял всю пачку).
Т13. **Фото 10–15 МБ**: лимит тела через middleware — 16 МБ (`experimental.middlewareClientMaxBodySize`), маршруты
    проверяют 15 МБ и `Content-Length` > 16 МБ с понятной ошибкой 413. Запись голоса мультфильма (до 50 МБ по коду) тоже
    упирается в 16 МБ — реплики короткие, на практике < 2 МБ.
Т14. **Телефон получателя печати** — только мобильный, приводится к `+7XXXXXXXXXX`; имя получателя без ссылок и разметки.
    Для PDF телефон необязателен (неверный — не сохраняется).
Т15. Мелочи: `/chek/не-UUID` → 404; страницы кабинета без входа — переход ко входу без ошибки в логе (`userOrLogin`);
    вебхук выключенного способа оплаты → 404 без внешних запросов, id платежа ЮKassa проверяется и кодируется; отписка —
    страница с кнопкой (GET ничего не меняет), повтор — без новой записи согласия; один отзыв на заказ (последний
    оплаченный без отзыва); коды входа в журнале и консоли — «••••••», адрес — маской; IP — последний адрес
    X-Forwarded-For (его дописывает Caddy), `TRUSTED_PROXIES` — прокси перед Caddy (адреса или префиксы «10.0.»);
    **порт 3000 не должен быть доступен снаружи** (иначе адрес подделывается); подростки — 11–17 лет на сервере; заказ
    без выбранного способа оплаты отменяется через 48 часов; фото к готовой/оплаченной книге не принимаются; ссылка на
    чек в письме — абсолютная.
Т16. **«Как к вам обращаться»** — `User.firstName` (необязательно, до 40 символов: буквы, пробел, дефис; апостроф —
    нет). Задаётся при входе (пустое поле не стирает сохранённое) и в «Моих данных» (`/api/me`, action `name`, пусто —
    удалить); приветствие в кабинете и получатель по умолчанию (адресная книга и прошлый заказ — приоритетнее); в выгрузке
    данных есть, при удалении аккаунта стирается.
Т17. **Тесты сотрудников без лимитов покупателя**: сессия владельца/оператора/маркетолога не считает сказки с устройства и
    сети, превью на контакт, переписывания, перерисовки, смены настроения. Расходы ИИ по книгам сотрудников —
    `GenerationCost.staff = true`, свой лимит `limits.staffDailySpendRub` (1000 ₽/сутки, Настройки → Лимиты), отдельная
    серия на графике «Расходы на ИИ»; лимит покупателей (`dailySpendRub`) их не видит. Книга считается «сотрудника» по её
    владельцу (анонимная книга до входа — покупательская). Простой GPU (`gpuTick`) — общий расход, без признака.
Т18. **Миграции.** 0006 сверена: БД после `scripts/migrate.mjs` и БД из `prisma migrate diff --from-empty
    --to-schema-datamodel` совпадают (pg_dump схемы без учёта порядка колонок; `--from-url` с адаптером Prisma 6 не
    работает, бинарный движок схемы недоступен). Новая — 0007_security_fixes (firstName, коды восстановления, mfaAt,
    recoveryShow, GenerationCost.staff), сверена тем же способом.
