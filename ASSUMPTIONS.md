10. Отзывы на сайте показываются только из БД после модерации; пока их нет, секция скрыта.
11. CSP пока разрешает inline-скрипты (нужны Next.js); на шаге 7 заменяется на nonce.
12. Срок обращения по браку — 14 дней после получения; срок возврата денег — 10 дней.

## Шаги 4–7

27. Prisma работает без бинарных движков (WASM + драйвер pg); миграции применяет scripts/migrate.mjs,

30. Себестоимость генерации считается по цене часа GPU из настроек (300 ₽ — ориентир, сверить с прайсом Yandex Cloud).
31. Блок книги для печати: страница посвящения + 24 страницы сказки + финальная страница = 26 страниц; корешок
    и загибы обложки — по типовым значениям, сверить с шаблоном типографии.

## Контент-движок (4 аудитории)

35. Каталог сайта — таблица `Story`, заполняемая `prisma/seed.ts` из реестра `src/content` (upsert по slug): поля движка
    (аудитория, сегменты, голос, стили, вид героя, поводы, тема, план) обновляются при каждом seed, тексты витрины, SEO,
    обложка и включение из админки — не перезаписываются. Пустая/недоступная БД — каталог берётся из реестра.
36. Поводы: посадочные страницы для всех 22 поводов профилей (кроме «свой» и «без повода»); любой сюжет дарится на любой
    повод — повод вплетается в развороты 1 и 12 (`applyOccasion`), на странице повода сначала сюжеты с этим поводом.
37. Вход: телефон обязателен (+7, мобильный), код приходит на почту (настройка `auth.phoneRequired`, по умолчанию да).
    Сотрудникам и покупателям с уже сохранённым телефоном телефон при входе не нужен. Телефон, закреплённый за другим
    аккаунтом, не переносится — покупателя просим войти с почтой того аккаунта.
38. Смена настроения иллюстраций: до оплаты — бесплатно перерисовываются обложка и 2 разворота превью, не больше
    2 раз (`limits.moodChangesPreview`) и только в пределах суточного лимита расходов; после оплаты первая смена
    перерисовывает всю книгу (13 иллюстраций) и PDF бесплатно, каждая следующая списывает одну бесплатную перерисовку,
    а когда они кончились — платно, как перерисовка (`limits.redrawPriceRub`, через поддержку). Пока картинок нет —
    настроение просто запоминается.
39. «Своя история»: голос — выбор покупателя, иначе первый голос сегмента (`segment.textStyleIds[0]`); сегмент — явный,
    иначе по возрасту героя (питомцы — по виду: собака/кошка). Демо-текст своей идеи — сюжет сегмента в этом голосе.
40. Стиль картинок другой аудитории (например, детская акварель для кошки): из промпта убирается фраза художника о
    «своём» герое и добавляется описание героя по виду; спорящие слова негатива (например, «human body» у стилей
    питомцев для ребёнка) убираются. Если сцена прямо просит костюм — запрет костюмов снимается (просьба art/pets.ts).
41. Подписи PDF по аудитории: «Сказка, в которой…» — только для детей, для остальных — «История, в которой…»;
    возрастная маркировка на обложке: дети и питомцы 0+, подростки 6+, взрослые 12+ (сверить с юристом по 436-ФЗ).
42. Демо-рендер: доп. герои стоят рядом с героем без перекрытия (шаг по ширине фигур, группа сдвигается в кадр),
    вторая половинка — в полный рост героя, хозяева питомца — чуть дальше и мельче, чтобы питомец оставался главным.


## Витрина и анкета (UX, как у Wonderbly)

43. Сначала книга, потом герой. Книга выбрана (карточка, страница книги, повода — `?skazka=`) — анкета не спрашивает ни повод,
    ни сюжет: Герой → Внешность и что любит → Кто ещё в сказке → Стиль и посвящение (шаг «Кто ещё» пропускается, если добавить
    некого: у пар имя второй половинки — на шаге «Герой»). Повод такой книги — из ссылки (`?povod=`), иначе единственный повод
    книги (новогодняя, ко дню рождения), иначе «без повода». Без книги: «Для кого книга?» → «Какой повод?» с книгами под чипсами
    (сначала написанные к поводу — «к вашему поводу», остальные — «впишем ваш повод»; для «Своего повода» первой — «Своя история»).
44. Согласия — один раз, в первой точке сбора данных: путь с фото — две отдельные галочки перед загрузкой (ПДн; фото — по
    аудитории: «как законный представитель» / «своё фото или с согласия изображённых» / фото питомца), на входе — «Согласие
    дано ✓»; без фото — галочка ПДн на входе. Сервер не требует согласие повторно, если оно уже есть (по аккаунту или анонимной
    cookie) и не создаёт дублей; согласия до входа закрепляются за аккаунтом. Тип в БД для фото — `CHILD_PHOTO` для всех аудиторий.
    Рассылка — отдельная необязательная галочка только на входе.
45. Сезон на главной: с 15 октября по декабрь — Новый год (кнопка «Выбрать новогоднюю книгу», пункт меню); режим и срок печати
    меняются в Настройках → «Сезон на главной». Срок печати по умолчанию: праздник − 7 дней доставки − 5 рабочих дней печати.
46. Подписка «−300 ₽» на главной видна только при активном промокоде в Настройках → «Подписка на главной»; подписка создаёт
    покупателя с согласием на рассылку и показывает промокод (письмо не отправляется).
47. Иллюстрации на витрине, в каталоге и «живая обложка» анкеты — демо-рендер `/obrazec` (SVG, подписано «пример»). Настоящие
    пары «фото → иллюстрация» — только с письменного согласия, через `public/showcase/showcase.json` (см. README там же).
48. Тёмная тема: системная по умолчанию, переключатель в подвале (Авто/Светлая/Тёмная, хранится в браузере).

## Исправления по ревью (контент и безопасность)

49. Название с «[Имя]» — один помощник `src/content/title.ts`: падеж по предлогу перед [Имя] (о/об/при → предложный,
    для/у/от/без → родительный, к/по → дательный, с/за/под → творительный, иначе именительный); им пользуются текст
    книги, бриф, живая обложка анкеты, карточки каталога, страница книги, SEO и PDF (через текст книги).
50. Предлог перед подставленным именем/поводом исправляет fillTags: «об» перед а, о, у, э, и, ы (перед е, ё, ю, я —
    «о»: «о Юле»), «со» перед стечением согласных (Льв-, Вс-, Св-, Ст-, Зв-, Шк-…), «ко» — перед Вс-/Мн-; регистр сохраняется.
51. Свободный текст анкеты (внешность, приметы, характер питомца, как познакомились, воспоминания, описания и «что это»
    доп. героев, свой повод, идея) перед YandexGPT обезличивается (`src/lib/gen/redact.ts`): все падежные формы имени,
    домашнего имени, доп. героев и частые ласковые формы из таблицы (Аня ↔ Анна/Анечка/Анюта…) + уменьшительные
    суффиксы → метки {ГЕРОЙ.*}/{ЛАСКОВО.*}/{ДОПn.*}; в промпт картинок — «the hero», «the friend». Телефоны, почта,
    ссылки, @ники и числа от 6 цифр удаляются. Имена-слова (Любовь, Лев, Вера…) ищем только с заглавной. Редкие
    домашние имена, которых нет в таблице и которые не образованы суффиксом от имени, распознать нельзя — поэтому
    под полями подсказка «Имена здесь не нужны — мы подставим их сами».
52. Промокод и скидка новичка не суммируются: побеждает та, что даёт больше рублей на этом заказе (при равенстве —
    скидка новичка, промокод не тратится). Применённый промокод записывается в заказ; при оплате usedCount растёт
    одним условным UPDATE (`usedCount < maxUses`). Если лимит исчерпан между заказом и оплатой — оплата принимается,
    владельцу уходит уведомление.
53. Списание лимитов книги (переписать, перерисовка, смена настроения до/после оплаты) — условный UPDATE
    (`updateMany` с проверкой остатка и статуса); в очередь задача ставится, только если списание прошло.
54. Повод в тексте — короткая форма (`OCCASION_WORDS`: «годовщина», «выход на пенсию», «новоселье», «первое сентября»…)
    с родом и падежами ({ПОВОД.дат}); «свой повод» не склоняется. В начале фразы, строки или цитаты — с заглавной.
55. «Месяц ясный» (дети): ребёнок не выходит из дома один — Сова прилетает к окну, путешествие — сон под её крылом.
56. Стихи: имя и повод — только отдельной строкой-обращением вне метра, не больше 4 имён на книгу; в стихотворных
    строках — «ты», «весь дом», «непоседа», формы рода равной длины (дедушка/бабушка). Правило — в системных промптах
    стихотворных голосов и в validateContent.
57. Вход: код — только на почту; цель-телефон ({target:"+7…"}) принимается лишь при включённой настройке
    «Вход по SMS-коду» (`auth.smsLogin`, по умолчанию выключено). Телефон обязателен и при проверке кода (если
    `auth.phoneRequired` и у покупателя его нет) — проверяется до кода и сохраняется в профиль.
58. Сказки в сутки: кроме лимита устройства — лимит по подсети IP (IPv4 /24, IPv6 /64), по умолчанию 10
    (`limits.textsPerIp`). Текст YandexGPT, как и превью, ждёт в очереди, если исчерпан суточный лимит расходов (демо — бесплатно).
59. Заголовок `Origin: null` или некорректный Origin у POST к /api — 403 (раньше — 500).
